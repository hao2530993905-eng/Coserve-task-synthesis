# 多模态来源与素材清单

## 选材与格式核对

数据集的直接链接与可用素材类型见 [主文件的链接清单](../SKILL.md#公开数据集链接)。选定来源后，直接在官方页面核对本次要用的文件与样本。

- ECCV：用划分和样本 ID 共同定位；公开测试样本不提供目标 STEP；归一化尺度与物理单位分别记录。
- CADFS：全精度与低精度脚本可能有差异；CoServe 的可编辑建模任务需要迁移 FeatureScript 几何语义。
- Text2CAD：按 UID 配对，确认访问条件、版本和实际发布的图像、序列文件。
- STEP-LLM：图像与原始 ABC STEP 分别获取；配对依据是模型 ID，不能假定图像仓库已经包含真值模型。
- Fusion 360 Gallery：区分重建、面分割与装配子集；重建文档的长度单位为 cm，角度为 rad，使用前核对。
- ABC 与 DeepCAD：按所选样本确认模态齐备情况；自行渲染时记录过程，不称为原始实拍图。
- MCB：网格不自动具有制造尺寸、参数化特征或精确 B-rep；补充测量与格式转换分别记录。
- BrepGen：张量和处理数据不等于可直接导入的 STEP；实际使用的原始或生成文件应可追溯。
- SldprtNet：重新核实发布和下载状态，未获取实际样本时只记为候选来源。

## 素材配对

有输入文件或待准备素材的任务在 CSV 外记录素材清单，可使用 `素材清单.json` 或项目已有格式；用稳定 `task_id` 关联，保留以下信息。

| 信息 | 用途 |
| --- | --- |
| 稳定 `task_id` 与对应的完整任务文本 | 关联 CSV 记录，避免依赖行号 |
| 数据集、版本或修订、划分、样本 ID、来源链接 | 明确使用的是哪个真实样本 |
| 用户输入文件列表、模态与相对路径 | 确定用户实际发给智能体的图片、图纸、原 CAD 或尺寸表 |
| 文件提供方式与时机 | 区分初始聊天附件、项目预置文件和后续补传；补传只记录条件，不预写用户台词 |
| 参考模型或其他验收资料及其用途 | 区分重建真值与修改任务的输入模型 |
| 单位、尺度、视图、坐标约定 | 保留源资料中的已知条件，未知值明确缺失 |
| 素材用途与生成信息 | 区分用户附件、环境构建数据和评测专用数据；生成素材记录构造参数，供后续查找与核对复用 |
| 素材状态与核对记录 | 区分待绑定、已配对和已实际执行；记录文件存在、可读性与配对依据 |
| 许可或使用条件的官方出处 | 支持按资产与发布版本核实用途 |

图片、CAD 模型、网格及环境构建生成的数据都使用主 skill 指定的统一数据目录，可按来源、任务或运行标识组织子目录。准备新任务时先在此查找并核对可复用素材，新增素材也写入此处。CSV 的 `上传文件`使用相对于该目录的路径，只列初始消息附件；运行时经聊天附件入口提交。后续补传文件按实际交互提供，并在素材清单记录。项目预置文件在素材清单记录来源，在 `环境准备`中说明如何布置到本次新环境，详见 [环境准备说明](environment-preparation.md)。不要把预置文件当成已经完成聊天上传，也不要在用户题面中统一要求把文件放进项目目录。

设计阶段尚未取得的附件可列计划相对路径，但必须在素材清单中标记“待准备”，整题仅作为任务设计交付。交付可执行数据前，逐项核对附件存在、可读、与题面配对；评测答案可保存在统一目录内的评测专用子目录并明确用途，不列入上传文件或复制到执行任务的项目中。

下载本次任务需要的文件，避免把整个大数据集下载当成默认准备步骤。公开文件可直接读取或下载；访问需登录、申请或接受条款时，遵循当前工具和用户授权，不绕过访问限制。

核对模型标识是否一致、图片是否属于同一零件、文件能否读取，以及源资料中已知的单位与视图是否匹配。文件存在和哈希一致只证明文件身份，不能证明几何、图纸或用户目标已经核对正确。

图像输入应保留任务真正需要的视觉信息。不要先把图片完整转写成文字，再让智能体只读文字；也不要在题面中加入仅由隐藏目标 CAD 才能获得的尺寸。

从公开训练集构造看图重建任务时，可以另划本地验证集，目标 STEP 保留在评测侧。以原始模型标识对 ABC 及其派生数据分组去重，避免同一几何通过不同来源进入训练和评测两侧。
