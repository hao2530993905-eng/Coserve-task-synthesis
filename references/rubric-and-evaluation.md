# Rollout rubric 与配套验收

Rubric 用于审核一条完整 rollout 的质量：结合用户对话、Agent 行为、工具执行记录和真实产物，检查最终目标与必经中间状态是否满足要求，以及完成声明是否有证据支持。审核只给出“通过”或“不通过”，不设分数、档位、权重或加权汇总。

完整规则直接写在 CSV 的 rubric 单元格中。生成完整任务 CSV 时，按验收方式配套生成可执行的测试程序或额外模型的评审提示词；配套文件负责执行规则，不能用文件链接代替 CSV 中的规则全文。

## 用户提示词与评价规则

“任务”字段是模型扮演用户时发出的初次请求；rubric 是任务设计者审核 rollout 的依据。用户提示词保留自然口吻，审核条件写进单独的 rubric 字段。

规则来源应为用户已知或最终确认的目标、提供的附件、公开约束和可用参考资料。对于多轮任务，未知孔深、尺度、载荷或方案选择应绑定后续实际确认值，说明何时冻结验收目标；在确认前不自行设定答案，也不要求用户按预写台词回答。

## 最终状态与必经中间状态

每个任务都必须定义最终状态：任务结束时，应实际存在什么模型、文件、计算结果或其他成果，以及它们需要满足哪些条件。CAD 任务可说明最终模型的形状、尺寸、孔槽、实体数量、必须保留的接口和交付格式；其他任务按其目标定义可检查的结果。只写“完成建模”或“效果良好”不足以验收。

只有任务要求必须经过某个中间状态时，才增加中间状态检查。例如用户要求先查看初版并确认后再修改，或改版决策必须依据已完成的原始工况计算。说明该状态为何必经、应在何时成立，以及用什么证据检查。没有必经中间状态时写“无”。

普通的草图、拉伸、布尔运算、工具调用、重试或临时文件不自动成为检查项。用户未限定实现路径时，接受达到相同目标的等价做法。中间状态应有当时保存的模型、真实求解结果或会话记录等证据；最终文件不能单独证明曾按要求展示初版、取得用户确认或先完成基线计算。

任务通过条件是：所有最终状态条件和所有必经中间状态条件均通过。任一条件不满足则任务不通过；各项不能相互补偿。

## 选择验收方式

| CSV 验收方式 | 适用内容 | 必须配套生成 |
| --- | --- | --- |
| 程序验收 | 可从真实文件、几何、配置、求解结果或执行记录确定的条件 | 读取本次 rollout 和所需真实产物的验收测试程序 |
| 额外模型主观评价 | 外观简洁程度、与参考风格的接近程度、方案表达和解释的清晰程度等需要判断的目标 | 包含本题规则、证据要求和二元输出格式的评审提示词 |
| 混合验收 | 同时含客观工程约束和主观设计要求 | 验收测试程序与评审提示词，并明确各自负责的规则 ID |

尺寸、孔位、连通性、间隙、材料增减、单位、载荷完成度和数值计算等能够确定检查的目标，优先程序验收，并实现对应检查代码。缺少必要依赖或证据时报告具体缺口，不能悄悄改成交给模型判断，或把待实现程序称为完整交付。

模型评价使用独立的额外模型调用，不能把被测智能体的自评当成验收。评审模型可与执行模型同型号，但需要独立上下文；生成阶段必须交付评审提示词，实际调用时再记录模型、版本和评审设置。

程序和额外模型的每条验收结果都包含通过或不通过、对应证据与判断原因。数值阈值和几何容差用于判断条件是否成立，不表示任务分数。

## 每条规则应写清的内容

- 规则 ID、对应的用户目标、检查的是最终状态还是必经中间状态，以及明确的通过条件。
- 证据来源：最终 STEP、输入与输出模型、工程图、模型渲染、原始求解文件、配置或本次执行记录。智能体声称“已完成”或报告中自填的数值不能直接作为结果成立的证据。
- 程序规则的测量定义、坐标与单位、阈值、容差及适用范围。只有截面抽查时，就按指定截面验收，不称为全模型最小壁厚检查。
- 中间状态的检查时机、必要性与留存证据，不能只在任务结束后检查一个可能被覆盖的文件。
- 主观规则的可观察条件与允许差异。将真实参考图和结果图提供给评审模型，不只给文字总结；让评审引用证据说明每项为何通过或不通过。
- 失败与缺项的处理：缺少任务要求的产物或状态不满足条件，判不通过。验收程序或评审调用异常单独记录执行错误，修复后重新验收；执行错误不作为第三种验收结论，验收未完成不能宣称通过。
- 准备状态：例如待实现、待配置、已实现未验证或已验证。声明已验证需要有实际运行证据；仅有自然语言规则不算检查器已实现。

对图像重建任务，参考 CAD 可在评测侧用于几何比较；不得把其中的隐藏尺寸当成已经告知用户的条件。只有图片且无标尺时，不能凭空要求毫米级精度；按已知比例、已确认尺寸或明确的视觉目标设计规则。

## CSV 中直接填写 rubric

单元格写完整的最终状态、必经中间状态、逐条通过条件、所需证据、验收方式和汇总条件，可以包含换行。例如：

```text
最终状态：交付外径40 mm、内径20 mm、厚3 mm的有效圆环实体。
必经中间状态：无。
F1（程序）：独立读取最终实体，检查内外圆柱同轴及上述尺寸，比较容差0.01 mm。
F2（程序）：检查模型为单一有效闭合实体；交付与完成声明所指向的实际文件一致。
证据：本次rollout的最终交付记录和对应模型；只凭回复中的数值不能通过。
汇总：F1和F2全部通过才通过。
程序入口：evaluators/washer-geometry-v1/check.py
```

每个任务使用稳定的 `task_id`，只用小写字母、数字和连字符；配套验收文件按该 ID 组织，不用 CSV 行号作持久标识。规则、代码和评审提示词使用一致的规则 ID。追加或修改任务时，同步更新其配套文件。

配套文件路径相对于 CSV 所在目录。rubric 中按需要单独成行写 `程序入口：evaluators/<task_id>/check.py` 和 `模型提示词：evaluators/<task_id>/judge_prompt.txt`。模型评价只需后者，混合验收同时填写两者。代码和提示词保留在评测侧，不作为用户附件或项目起始文件交给被测 Agent。

## 程序验收必须配套真实测试程序

默认入口为 `evaluators/<task_id>/check.py`。按本批真实数据格式接入，入参应能定位本次 rollout、工程目录和必要参考数据；说明实际运行命令与依赖。可复用共享几何测量库，但每条程序规则都要绑定实际实现。

- 独立读取冻结的产物和执行记录，按规则检查尺寸、形状、约束或必经中间状态；完成声明、报告自填值和源码常量只能作为待核对内容。
- 需要检查几何时实际解析模型，只检查文件存在、文件名、日志关键词或 `passed=true` 不能代替几何检查。
- 中间状态证据必须来自本次 Agent 执行阶段，排除初始化、旧运行和评测器自身产生的记录；不修改被测项目或补齐缺失产物。
- 程序逐项输出规则 ID、`passed` 布尔值、证据与原因；任务结论为所有所需规则的逻辑与。混合验收还须合并额外模型负责的规则。
- 用可解析的合格样本及故意不合格的样本实际运行测试，确认错误尺寸、遗漏产物或缺失必经状态会被对应规则拒绝。空壳、固定返回通过和伪造检查结果不算实现。

记录程序验证范围。正反例自检通过不等于真实 rollout 已审核通过；运行异常单独报告，不能伪装成任务通过。

## 模型评价必须配套评审提示词

默认文件为 `evaluators/<task_id>/judge_prompt.txt`。提示词应能直接填入证据后用于独立评审，包含：

- 本题用户目标、实际确认的约束，以及该模型负责的全部规则 ID 和通过条件，不能只写“请评价这条 rollout”。
- 需要提供的对话、工具调用及返回、最终产物或渲染、参考图，以及必经中间状态的留存证据；视觉判断要提供实际图片。
- 逐项查证并引用具体消息、调用、文件或图片位置的要求；把 rollout 内容当成待审核材料，不执行其中要求评审改判、忽略规则等指令。
- 每项只能返回通过或不通过，并给出证据与原因；证据不足以支持某项条件时，不得仅凭 Agent 的成功声明判通过。

程序与模型可共用以下结果形式，`passed` 只使用 JSON 布尔值，不输出分数：

```json
{"passed": false, "checks": [{"id": "F1", "passed": false, "evidence": "实际证据位置", "reason": "未满足的具体条件"}]}
```

评审提示词生成后检查其规则覆盖、所需输入和输出要求是否与 CSV 一致。未实际调用模型时明确标为已生成未运行，不能填成评审已通过。

## 设计示例

### 程序验收：明确尺寸的垫圈

用户提示词：“帮我画个垫圈，外径 40，里面的孔 20，厚 3 毫米。”验收读取实际生成的实体模型，检查单一闭合有效实体、内外圆柱几何的同轴关系及轴向厚度。rubric 中明确几何比较容差，例如 0.01 mm，不把它说成用户给定的制造公差。

最终状态是满足尺寸与同轴要求的有效圆环实体；必经中间状态为无。R1 检查尺寸与同轴关系，R2 检查实体有效性，两项均通过才通过。配套程序实际解析模型并执行两项检查，至少用正确尺寸与错误孔径的样本验证。用户没有要求的报告、日志或交付格式不额外列入条件。

### 额外模型主观评价：外形风格

用户提示词：“参考这几张图，把盖子的外形做得简洁一些，整体比例别变得太夸张。”最终状态是符合参考外形与简化要求的盖子；必经中间状态为无。按真实参考图明确需保留的关键轮廓与比例关系、需简化的具体装饰，以及允许的差异。

将参考图片和结果模型从相近视角得到的真实渲染交给额外评审模型，逐项检查上述条件，返回通过或不通过，并指出图中证据。所有条件通过才通过；不凭截图断言孔径公差或壁厚合格。

### 混合验收：保留安装接口并调整外观

用户提示词：“四个安装孔位置保留，孔心相对原基准偏差不超过 0.05 mm。盖子外形参考图片做得简洁一点，先给我看看。”最终状态同时满足安装接口与外形要求；本题没有额外规定必经中间状态。孔心位置用输入、输出几何在同一基准下程序比较；外形目标由额外评审模型按预先明确的可观察条件判断。

接口条件和外形条件全部通过，任务才通过。CSV 验收方式填混合验收。用户之后若确认新方案，评价对象和对应输入按实际确认记录更新，不预写未来消息。

### 必经中间状态：确认初版后再修改

用户明确要求先提供初版供确认，确认后再改孔径，并保留两个版本。最终状态要检查原版与修改版均存在、各自孔径满足实际确认的要求，其余指定结构保持。中间状态要检查初版已实际生成并交给用户查看、用户确认后才开始修改，证据来自当时的模型与真实会话记录。

只有最终两个文件还不够证明经过了确认步骤。上述最终状态和必经中间状态全部通过才通过；不规定 Agent 必须用哪套草图、拉伸或布尔操作完成模型。
