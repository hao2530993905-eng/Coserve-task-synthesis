# 环境准备

`环境准备`描述任务运行侧在每次会话任务开始前，由脚本构建的独立初始环境。每次独立采样都创建新环境；同一会话的后续多轮消息继续使用当前环境。

多模态输入按主 skill 指定的位置提前准备，聊天附件随消息提供。这属于输入数据准备与消息投递，不写成环境构造步骤。环境构造负责项目、工作台、配置和其他任务所需的初始状态。

## 每次初始化

1. 为本次任务创建独立项目和工作目录，准备本题所需的工具与运行配置。已安装的运行环境可以复用，无须每次重新安装。
2. 需要初始模型或其他数据时，先检查约定的数据目录，核对文件可读、版本、单位和几何是否符合本题起始条件。已有合适素材就复用；可自行构造的数据缺失或不符合时，才用生成脚本构造并保存供后续复用。公开数据集的原始素材按来源获取，不能用临时造型冒充。
3. 把起始数据布置到新环境中。需要工作台预先显示模型的任务，每次都须导入并加载该模型；已有 mesh 文件只省去生成步骤，不能省去新环境中的导入。按题意设置初始参数、视图、配置或历史版本。
4. 检查初始化完成条件，再开始用户对话。例如确认当前项目、文件路径、模型加载状态和初始参数；需要真实模型时，默认展示样品不能代替它。准备失败应报告环境错误，不继续发送依赖该环境的任务。

复用的是起始素材和已安装的运行环境。上一轮被修改的项目、模型、对话和求解结果不能作为本次初始状态。执行任务的项目中只准备题目要求的起点，不放入预先完成的答案或评测专用资料。

## CSV 填写

单元格简述本题的新环境、所需初始状态和准备完成条件；已有初始化脚本时，附上实际入口与必要参数。脚本接收本次项目或工作目录，不能写死上次运行的项目 ID。

字段示例：

- 修改工作台现有法兰：创建独立项目；检查数据目录中初始法兰，缺失时调用生成脚本；每次将其导入并加载到新项目工作台，确认四个安装孔的分布圆直径为 72 mm 后开始会话。
- 从零建模：创建独立项目，确认 CAD 工具可用，工作台没有预置的真实模型。
- 根据上传图片建模：创建独立项目，确认 CAD 和图片读取工具可用，项目中不预置待重建的目标模型。

环境准备不限于文件，也可涉及本题必需的参数化工程、配置、服务状态或版本记录。按任务实际需要安排，不统一套用“生成 mesh 并导入”的模板。

只设计任务时，明确记录初始化脚本待实现；交付可执行任务数据时，提供对应脚本并验证每次独立启动能得到要求的初始状态。只有实际运行后，才标记环境准备已验证。
