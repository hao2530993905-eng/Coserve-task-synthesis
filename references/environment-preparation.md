# 环境准备

`环境准备`描述任务运行侧在每次会话任务开始前，由脚本构建的独立初始环境。每次独立采样都创建新环境；同一会话的后续多轮消息继续使用当前环境。

生成完整任务 CSV 时，每题必须配套生成可运行的 `environments/<task_id>/prepare.py`，包含从零建模所需的空项目初始化。不能只交付文字说明、伪代码、空壳程序或标记为待实现。

多模态输入按主 skill 指定的位置提前准备，聊天附件随消息提供。这属于输入数据准备与消息投递，不写成环境构造步骤。环境构造负责项目、工作台、配置和其他任务所需的初始状态。

素材查找与环境生成数据都使用主 skill 指定的统一数据目录。环境脚本产生的模型、网格、初始配置及其他数据，保存到该目录内本题或本次运行的子目录；需要导入工作台时，再从这里导入本次独立项目。可复用的起始素材保留原件，项目中使用独立副本，运行专用数据按运行标识保存，避免覆盖其他任务或污染下次初始化。

## 每次初始化

1. 为本次任务创建独立项目和工作目录，准备本题所需的工具与运行配置。已安装的运行环境可以复用，无须每次重新安装。
2. 需要初始模型或其他数据时，先在统一数据目录中查找，核对文件可读、版本、单位和几何是否符合本题起始条件。已有合适素材就复用；可自行构造的数据缺失或不符合时，才用生成脚本构造并写回同一数据目录供后续复用。公开数据集的原始素材按来源获取并保存到此目录，不能用临时造型冒充。
3. 把起始数据布置到新环境中。需要工作台预先显示模型的任务，每次都须导入并加载该模型；已有 mesh 文件只省去生成步骤，不能省去新环境中的导入。按题意设置初始参数、视图、配置或历史版本。
4. 检查初始化完成条件，再开始用户对话。例如确认当前项目、文件路径、模型加载状态和初始参数；需要真实模型时，默认展示样品不能代替它。准备失败应报告环境错误，不继续发送依赖该环境的任务。

复用的是起始素材和已安装的运行环境。上一轮被修改的项目、模型、对话和求解结果不能作为本次初始状态。执行任务的项目中只准备题目要求的起点，不放入预先完成的答案或评测专用资料。

## CSV 填写

单元格简述本题的新环境、所需初始状态和准备完成条件，并单独成行写 `环境脚本：environments/<task_id>/prepare.py`，路径相对于 CSV 所在目录。任务 ID 与本题验收程序或评审提示词一致。

脚本接入实际启动流程：创建本次独立项目，或在启动器刚创建的空项目中布置初始状态。接收本次服务地址、统一数据目录、运行标识或项目参数，不能写死上次运行的项目 ID；环境生成数据的输出位置也基于该数据目录解析。注明实际运行命令与依赖。可调用共享初始化函数，但任务入口必须真正完成本题环境准备。

字段示例：

- 修改工作台现有法兰：创建独立项目；先在统一数据目录查找初始法兰，缺失时调用生成脚本并保存到同一目录；每次将其导入并加载到新项目工作台，确认四个安装孔的分布圆直径为 72 mm 后开始会话。
- 从零建模：创建独立项目，确认 CAD 工具可用，工作台没有预置的真实模型。
- 根据上传图片建模：创建独立项目，确认 CAD 和图片读取工具可用，项目中不预置待重建的目标模型。

环境准备不限于文件，也可涉及本题必需的参数化工程、配置、服务状态或版本记录。按任务实际需要安排，不统一套用“生成 mesh 并导入”的模板。

## 脚本输出与验证

- 就绪信息至少记录本次项目 ID、工作目录、实际准备的文件或配置，以及初始状态检查结果。需要加载模型时，应确认本次工作台已加载指定模型，不能只检查磁盘上存在 mesh 文件。
- 就绪检查全部通过后才返回成功，启动器随后发送任务。失败时返回非零退出码并记录原因，不发布就绪状态，也不把环境失败计为 Agent 任务失败。
- 至少实际启动两次，验证得到独立环境；确认第二次可复用合适的原始素材，但仍完成本次导入与状态布置。需要生成缺失素材的任务，还应验证生成分支；失败路径应阻止任务开始。
- 只准备任务起点，不提前替 Agent 完成改孔、建模或分析等题目目标；环境构建记录与素材保存在准备侧，不能当成 Agent 的执行证据。

保留实际验证记录，只有运行过的路径才标记为已验证。依赖或服务缺失时报告具体缺口；代码已生成但未运行不能称为环境已就绪。用户明确只要提示词时按该范围交付，其余完整任务 CSV 默认包含环境构建脚本。
